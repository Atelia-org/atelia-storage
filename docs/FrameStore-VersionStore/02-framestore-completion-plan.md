# FrameStore 收尾计划与自动队列入口

日期：2026-10-10。评估基线：`d67c097`，当时工作区干净。本文是可更新的实施调度，不新增设计合同；权威仍为 [S2](02-framestore-core.md)，独立交错构建消费要求见 [S3](03-framestore-interleaved-builders-and-durability.md)。

## 估计与完成边界

**当前已完成 R1–R3；S2/S3 独立源码资格已 Accepted。** 详细出口与证据见[最终源码验收](02-framestore-final-acceptance.md)。没有待处理的 R4 缺陷；后续相同自动任务只核对当前状态并结束，不继续扩展功能或重复取证。

用户在收尾后另行批准的 FrameAddress 变长 codec 与 RootMap 格式调整，单独记录于[变长编码实施记录](02-framestore-varint-address-implementation.md)，不重新开启 R1–R4 自动队列。

最初预计 3 轮主线及至多 1 轮修复余量。下文保留这三轮的范围与执行规则，供追溯；包交付和 VersionStore 仍需另行安排。

终点是 FrameStore 独立源码能力和 S2 系统验收闭合，并取得直接相关的 S3 public 构建消费证据。Create/Open/RO、三种追加、交错 Builder、随机读取、确认、归档及 Inventory/Audit 已实施，不再预设还要增加一轮功能框架。后续允许修复验收发现的实际缺陷。

当前三片证据分别为[格式与运行核心](02-framestore-core-implementation.md)、[持久化闭环](02-framestore-persistence-implementation.md)、[同步物理检查](02-framestore-inspection-implementation.md)。既有数百个单测、磁盘残留构造和局部故障注入不能代替真实子进程中断、规模测量或整个 S2 的逐项验收。

当前仍为 source-only；本计划不包含生产包注册/打包、公开发布、消费仓切换、VersionStore、conditional-update、批量规划器、并行 writer 或新的资源管理框架。若后续要求本地 NuGet 交付，预计单独再安排 1 轮，消费 S6 的 pack/隔离 smoke 合同；公开发布另按授权处理。VersionStore 尚有自身设计和实施缺口，不沿用这里的轮次估计。

## 分轮安排

| 顺序 | 有界目标 | 建议委派边界 | 退出证据 |
| --- | --- | --- | --- |
| R1 | 跨进程 owner、真实终止与重开 | public 子进程探针；目录/恢复缺口反例；独立验收。主线程负责共享协议、修复集成和两平台运行 | 实际 FrameStore 的跨进程互斥/共享、kill 后锁释放、确认前后与活跃构建中断后的冷重开；关键窗口的证据种类和剩余缺口明确 |
| R2 | 独立消费者及资源/规模基线 | public 循环图消费者；有界资源/规模探针；复杂度与资源归属复核 | self-reference、A↔B、M=1 + Append 等已定轨迹读回；记录句柄、分配/内存和正式目录规模成本，修复明确的资源泄漏或意外复杂度问题 |
| R3 | 验收映射、必要补测与定稿 | S2 条款/测试映射；实现反例复核；public 指南与证据核对。主线程裁决全局出口 | 所有必需项有可追溯证据或明确阻碍；适当回归通过，形成最终源码验收记录并更新实际阶段状态 |
| R4（条件轮） | 消化前面实际发现且未修完的问题 | 仅针对记录在案的缺陷/证据缺口分包 | 修复和受影响验证完成，或报告具体外部阻碍；无剩余工作则结束 |

每轮允许根据当前事实调整拆分或合并已完成的工作。不要机械执行编号，不重复研究已定稿内容，也不把包交付或下一层实现塞进空余轮次。

### R1：跨进程与中断

先把 S2 现有验收条款映射到已有测试/探针，列出本轮真正缺少的过程证据。已有 [StoreOwnerLockProbe](../../experiments/StoreOwnerLockProbe/README.md) 只验证过锁原语，新的证据须消费实际公开 FrameStore。

使用父子进程显式握手确定已到达的阶段，不以固定 sleep 推断某次写入完成；只终止探针自己创建并记录身份的子进程。用新建隔离目录、可重跑命令和机器可读结果记录实际内容与恢复报告。Windows/.NET 与 Linux/WSL 分别取证，说明真实运行环境。

重点覆盖跨进程 writer/reader 模式矩阵、无 data/全部 archive 时仍持有控制锁、进程退出后重新打开、已确认地址保留、未完成 Builder 的放弃、多个 active 的独立恢复及归档前后地址稳定。确认未成功返回时只按磁盘实际事实裁决，不要求完整帧必然消失，也不把内存通信日志当作业务发布记录。

对 Create、private 初始化/发布、flush/close/rename 等内部窄窗口，明确区分真实强杀、受控故障注入、残留镜像和源码论证。public 边界停点不能证明命中了内部 syscall；先复用现有证据，必要时选择最小的内部可测试接缝，不新增公开故障开关或通用文件系统抽象。必需窗口若尚无充分证据，保留为具体缺口，不为结束本轮重标通过。只承诺已定的 ProcessCrashOnly，不扩展为断电资格。

### R2：消费与成本

先复用已有 public 测试，只补尚未实际证明的独立消费轨迹：12B 地址编码的单帧自引用、多个提前地址形成 A↔B 并乱序完成、M=1 时已知尺寸 A + 完整 Append B 后回填 A，以及取消/地址复用不能恢复旧构建来源。冷重开按地址解码比对逻辑图，不依赖文件选择和枚举顺序；不引入 VersionStore 或临时模拟发布协议。

资源探针采用有限、可配置、事先声明的磁盘/时长/数据规模，至少用多个规模点分别观察：retained active 与历史峰值、降低 M 后重开、大 sizeHint/重复较大 Append、反复读取与扫描失败后的资源释放、archive 数量增长时的 Open/Inventory/Audit 成本。区分句柄、托管分配、存活内存、池保留与 RSS，不把单次 GC 或工作集高水位当作泄漏判据。

报告环境、输入规模、缓存条件、重复次数和原始结果。测量用于验证已选基线及揭示意外增长；没有用户负载/SLO 时，不设武断吞吐门槛，也不借测量新增缓存、manifest、历史 ID 表或精确总资源配额。确实需要产品取舍的性能问题留给用户。

### R3：逐项收口

将 S2-Q1..Q7、实施出口和对应验收向量映射到实际 public/内部测试、故障注入、过程探针或明确推理。已有证明直接引用，不重新复制一套同义测试。S3 单列真实取得的消费资格，不把 FrameStore 功能齐全称作整个 S6 交付完成。

独立审查优先检查成功返回与故障边界、资源移交/清理、平台准入/恢复顺序，以及用户指南能否完全通过 public API 重现。修正实际缺陷和与当前代码不符的导航/状态文字；首次建立映射也可能发现此前未列出的必要补测，其归属留在本轮或 R4。

最终记录源码提交、平台/文件系统、运行命令、证据位置和未覆盖范围。只有实际满足出口才更新相应阶段的 Ready/Accepted 状态；包资格、真实应用接入及更广平台资格继续分开报告。内部可解决事项清理完毕但尚有必需证据缺口时，明确停在何处，不强行定稿。

## 自动循环规则与提示词

每轮先读当前 git 状态、本文进度和最新实施记录，选择一个尚未完成且边界清楚的目标。默认沿用 `gpt-6.1-sol / xhigh` 的有界 subagent 工作包；主线程先固定共享接口与写入所有权，再独立复核、集成和验收。Windows 下 build/test/pack 命令串行；先 Release build，再匹配配置的 `--no-build`。按需本地提交，保留已有工作，不推送。

每轮结束只更新本文相应进度行并链接该轮详细记录；未完成项写明具体缺口。若全部完成，或剩余必需事项依赖用户产品决策/不可取得的外部环境，报告并结束本次调用，不扩展需求或重复探测同一阻碍。若只是工作尚未做完，记录下一步，不把困难自动归为外部阻碍。

以下是本次队列使用的提示词；当前队列已完成，无需继续排队：

```text
请按 docs/FrameStore-VersionStore/02-framestore-completion-plan.md 推进 FrameStore 收尾。
以当前文件和 git 状态为准，自主选定一个尚未完成、边界清楚的本轮目标，
用 $bounded-delegation 带领 subagents 实施；优先 gpt-6.1-sol / xhigh。
主线程负责共享契约、独立复核和串行验收；按需编写探针、修复代码、更新进度/证据并本地 git 提交。
本队列只完成计划规定的 FrameStore 源码与系统验收，不自动进入包交付或 VersionStore。
若已完成，或剩余必需事项确实依赖我的决策/不可取得的外部环境，报告具体状态并结束；不要为凑轮次扩展需求。
```
